# MathLab

这个仓库用于系统学习 Python、科学计算和数学软件开发，并为以后研究理论物理与人工智能辅助数学打基础。

这里最重要的目标不是积累代码，而是逐渐做到：能独立写出程序，能判断结果是否正确，能解释设计理由，也能在需求变化时修改程序。

## 最重要的学习原则

1. **首次提交之前完全不使用 AI。** 阅读、Notebook 笔记、自选练习、测试和调试都由自己完成并提交，之后 Codex 才能查看当前学习内容。
2. **程序能运行不等于已经掌握。** 还要能够测试、解释和修改。
3. **先求正确和清楚，再考虑简短或快速。** 不为炫技使用复杂写法，也不在没有测量前优化。
4. **每个数学程序都要明确约定。** 写清定义、输入、输出、单位、符号、基底顺序和归一化方式。
5. **错误是学习材料。** 不只记录正确答案，还要记录错误假设、修复方法和防止复发的测试。
6. **数值吻合不是数学证明。** 始终区分符号恒等式、数值证据和严格证明。

## 每次学习的具体流程

### 一、开始前

1. 从[学习路线](docs/syllabus.md)中确定本次主题。
2. 用一句话写下今天要解决的问题。
3. 写下自己预计会用到的概念，不急着打开现有答案。
4. 如果是数学或科学计算问题，先完成下面的准备清单：
   - 数学定义和适用范围；
   - 输入与输出的表示方式；
   - 必须保持的性质或不变量；
   - 普通、边界、无效和数值困难情况；
   - 一个可以手算的小例子；
   - 准备用哪些测试判断正确性。

### 二、独立尝试

1. 先写最直接、最容易检查的版本。
2. 用手算例子逐行跟踪程序。
3. 为正常情况、边界情况和错误输入编写测试。
4. 运行测试，先观察实际结果，再修改代码。
5. 如果失败，先写下自己的预测和最可能出错的位置。

### 三、提交独立成果

完成阅读、笔记、自选练习、测试和独立调试后，先创建一个 Git 提交。这个提交保存 Codex 首次接触当前学习内容之前的原始证据。

提交前确认：

1. Notebook 笔记确实由自己选择和撰写；
2. 练习范围由自己决定；
3. 测试和调试没有使用 AI；
4. 没有把缓存、大型 Notebook 输出或秘密信息加入提交。

### 四、提交后使用 Codex

首次独立提交完成后，按下面的顺序进行：

1. 请 Codex 只读审阅笔记、练习、测试和代码，不修改文件。
2. 自己处理审阅意见并提交修正。
3. 请 Codex 进行第二次只读审阅。
4. 完成一次闭卷问答、代码答辩或空白文件测试。
5. 根据证据决定进入下一单元或增加练习。

可以直接使用这些提问方式：

- “我已经提交了未经 AI 协助的原始成果，请进行第一次只读审阅，不要修改文件。”
- “请主要检查我实际记录内容的正确性，不要把未选择的教材内容视为缺陷。”
- “请把正确性问题和可选的高价值遗漏提醒分开报告。”
- “我已自行处理第一次审阅意见，请进行第二次只读审阅。”
- “请根据当前提交为我进行闭卷问答或代码答辩，不要提前给答案。”

### 五、结束前

1. 保存第一次审阅、修正提交和第二次审阅的证据。
2. 不看代码，用自己的话解释算法和关键约定。
3. 完成闭卷检验，并记录暴露出的薄弱点。
4. 在[学习进度](docs/progress.md)中如实记录独立完成和 Codex 参与的部分。
5. 如果解决了一个重要误解，在[错误记录](docs/error_log.md)中留下条目。
6. 写下“进入下一单元”或“增加练习”的明确决定。

## 建议的每周节奏

### 周初

- 确定一个主要主题和一个可以完成的小成果。
- 回顾上周的错误记录和未解决问题。
- 为本周安排至少一次完全独立的练习。

### 周中

- 以短练习掌握概念，再把可复用内容放入正式代码。
- 每发现一个缺陷，就补充一个能复现它的测试。
- 保持笔记本用于探索，正式实现与测试分开保存。

### 周末

- 完成一次不看答案的回忆练习。
- 用“运行、测试、解释、修改”四个层次评价本周内容。
- 更新学习进度，只记录真实掌握的部分。
- 选择下周需要继续巩固的一个薄弱点。

## 如何判断自己是否掌握

对每个重要主题依次检查四个层次：

1. **运行：** 能让程序在一个代表性例子上运行。
2. **测试：** 能自己设计正常、边界、错误和回归测试。
3. **解释：** 能说明算法、约定、限制以及错误原因。
4. **修改：** 面对新要求时，能预判影响并独立修改代码与测试。

只有经过一段时间后仍能达到“修改”层次，才算真正掌握。每月应安排一次从空白文件开始的独立测试，具体方法见[评估标准](docs/assessment.md)。

## 遇到错误时的处理顺序

不要只寻找“正确的那一行”。按照以下顺序记录和分析：

1. **现象：** 实际发生了什么？完整错误信息是什么？
2. **最小复现：** 最少需要哪些代码才能再次出现？
3. **错误假设：** 自己原本认为哪条规则成立？
4. **相关规则：** Python、数学或数值计算真正遵循什么规则？
5. **修复：** 为什么这个改动能够解决问题？
6. **防止复发：** 什么测试可以保证问题不再悄悄出现？

可直接复制[错误记录模板](docs/error_log.md)进行整理。

## 仓库内容导航

- `exercises`：短练习，优先独立完成。
- `src/mathlab`：可以复用并经过测试的正式代码。
- `tests`：验证行为、边界情况和数学性质的测试。
- `projects`：特殊函数、角动量和薛定谔方程等长期项目。
- `notebooks`：探索、推导、实验和展示。
- `docs`：学习路线、进度、错误、概念清单和评估标准。

## 最常用的操作

运行测试：

```powershell
uv run pytest
```

启动交互式学习环境：

```powershell
uv run jupyter lab
```

环境或依赖发生变化后同步：

```powershell
uv sync
```

提交前执行完整检查：

```powershell
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run mypy src
uv build
```
